# @rabjs/kit 1.0 Modernization Design

Date: 2026-08-19
Status: Approved in conversation; awaiting spec review
Version target: `1.0.0`

## Problem

`@rabjs/kit` 0.0.3 presents itself as “lodash, but TypeScript and tree-shaking.” That story is no longer a differentiator (es-toolkit and remeda already own it). The repo also carries leftover TypeDI release scripts, handwritten 600+ line `exports`, mixed default exports, a Docusaurus site the owner no longer wants, and Dependabot upgrade PRs stacked against a stack we are replacing.

The library is still `0.0.3`. A 1.0 breaking cleanup is acceptable.

## Goal

Ship `@rabjs/kit@1.0.0` as a **full lodash-shaped TypeScript utility library** that is also **agent-readable**: same function names and main argument order as lodash, stricter types, immutable defaults, modern ESM/CJS dual publish, Vite + React docs, bilingual README, Changesets-powered npm publish, and in-repo skills / `AGENTS.md` / `llms.txt`.

This is **not** a slim “only the gaps” kit. Existing API surface stays. Native wrappers (`isArray`, `keys`, `padStart`, …) stay. Missing file-per-function splits and documented-but-bundled helpers get cleaned up.

## Differentiation (what we claim, honestly)

Do **not** market “TypeScript + tree-shaking” as unique.

| Claim                                          | lodash                | es-toolkit | @rabjs/kit 1.0                    |
| ---------------------------------------------- | --------------------- | ---------- | --------------------------------- |
| lodash-shaped names / arity                    | yes                   | mostly     | yes, explicit                     |
| TypeScript-native, no `any` in public APIs     | no                    | yes        | yes                               |
| Immutable by default                           | no (`remove` mutates) | mixed      | yes                               |
| Dual ESM + CJS, generated `exports`            | CJS-first             | yes        | yes (tsdown)                      |
| Agent assets (`llms.txt`, skills, `AGENTS.md`) | no                    | no         | yes                               |
| Interactive Vite catalog docs                  | no                    | partial    | catalog-first + per-fn playground |

**Positioning sentence (EN):** Typed lodash-shaped utilities for humans and coding agents.

**Positioning sentence (ZH):** 给人和 coding agent 用的、lodash 风格的 TypeScript 工具库。

## Constraints (locked)

- Keep the current ~112 public functions. Do not delete categories.
- Function names and primary argument order stay lodash-compatible.
- 1.0 **is** breaking: drop `export default`, tighten `any`, `remove` becomes immutable, generated `exports`.
- Docs stack: Vite + TypeScript + React 19. Docusaurus is deleted.
- Docs IA: **catalog-first** homepage (search + category cards). Each API page has a live playground.
- Tests: Vitest. Global coverage floor stays 90% branches/functions/lines/statements.
- Publish: Changesets + GitHub Actions → npm + GitHub Release. Docs deploy to GitHub Pages at `https://ximing.github.io/kit/`.
- Skills live **only in this repo** (`skills/`). Do not install them into `~/.grok/skills` or `~/.agents/skills`.
- Bilingual README: `README.md` (English) + `README.zh-CN.md` (Chinese), each linking the other at the top.
- Node `>= 20`. pnpm remains the package manager.
- `.superpowers/` (visual companion output) is gitignored. The spec under `docs/superpowers/` is committed.

## Non-goals

- MCP server package.
- Splitting the repo into `packages/kit` + `packages/docs`.
- 100% lodash coverage (no `_.chain`, no lazy sequences, no `fp` build).
- Installing skills onto the author’s machine.
- Keeping Rollup, Jest, or Docusaurus.

## Architecture

Single pnpm workspace with two packages:

```
kit/                          # @rabjs/kit (workspace root)
  src/                        # library, one named export per file
  test/                       # vitest, mirrors src
  scripts/                    # docs catalog generator only
  website/                    # Vite + React docs app
  skills/                     # three repo-local agent skills
  llms.txt                    # agent-facing API index
  AGENTS.md                   # how agents work in this repo
  CLAUDE.md                   # updated for 1.0 toolchain
  .changeset/
  .github/workflows/
```

Root remains the publishable library. `website` is a private workspace member. No extra publishable packages.

### Data flow

1. Source of truth for behavior and types: `src/**/*.ts` JSDoc + TypeScript signatures.
2. `pnpm build` (tsdown) emits `dist/` ESM + CJS + `.d.ts` and rewrites `package.json` `exports`.
3. `pnpm docs:catalog` reads `src/` and writes `website/src/generated/catalog.ts` (function metadata for the site and for `llms.txt` generation).
4. Website imports `@rabjs/kit` via workspace protocol and runs examples in the playground.
5. CI runs lint → typecheck → test → build → docs build. Release job publishes `dist` (or the package root with `files: ["dist"]`) to npm.

## Library 1.0

### Public API

Keep every current named export from `src/index.ts` and category indexes. Split helpers that today live as extra exports in a sibling file into their own files so deep imports match the function name:

| Today                         | 1.0 file                                 |
| ----------------------------- | ---------------------------------------- |
| `flattenDeep` in `flatten.ts` | `src/array/flattenDeep.ts`               |
| `uniqBy` in `uniq.ts`         | `src/array/uniqBy.ts`                    |
| `take`, `drop` in `zip.ts`    | `src/array/take.ts`, `src/array/drop.ts` |
| `remove` in `findIndex.ts`    | `src/array/remove.ts`                    |

Deep import paths stay `@rabjs/kit/array/take`, `@rabjs/kit/array/remove`, etc. Category index re-exports them.

### Breaking changes

1. **No default exports.** Every file exports only the named function (or named pair when a file still holds two tightly coupled helpers). Delete all `export default`.
2. **`remove` is immutable.**
   - Signature: `remove<T>(array: readonly T[], predicate: (item: T, index: number) => boolean): T[]`
   - Returns a **new** array containing elements for which `predicate` is true (the removed items), matching lodash’s return value.
   - Does **not** mutate the input. Callers who need the leftover array use `array.filter(negate(predicate))` or `partition`.
   - Document this in README / CHANGELOG as the lodash incompatibility.
3. **Public types drop `any`.** Replace with generics and `unknown` at boundaries. Internal casts are allowed only when hidden from the `.d.ts`.
4. **`RetryOptions.backoff`** in `src/types` currently says `'linear' | 'exponential'` but `retry()` uses a numeric multiplier. 1.0 types match the implementation: `backoff?: number` (multiplier, default `1`).
5. **Author / leftover copy.** `package.json` `author` becomes the repo owner (`ximing`). Release scripts no longer mention TypeDI or typedi URLs.
6. **Node / browsers.** Document Node `>= 20` and evergreen browsers (ES2020). Drop “Node 12 / Chrome 70” claims.

### Additive, non-breaking options

`delay`, `timeout`, and `retry` accept optional `signal?: AbortSignal`.

- If `signal` is already aborted, the returned promise rejects with that `AbortError` immediately.
- If aborted while waiting, pending timers are cleared and the promise rejects with the abort reason.
- Existing callers that omit `signal` behave as today.

### Implementation rules

- Named exports only.
- One public function per file after the splits above.
- Validate bad input the same way current functions do (return empty / `-1` / `false` rather than throw), except `retry` / `timeout` which reject.
- JSDoc on every public function: one-line summary, `@param`, `@returns`, at least one `@example` that is copy-pasteable TypeScript.
- No `sideEffects` other than `false`.
- `package.json` `type` is `"module"`. CJS is emitted as a second format, not the package default.

### Build

Replace Rollup + three `tsconfig.prod.*` files with **tsdown**:

```ts
// tsdown.config.ts
import { defineConfig } from 'tsdown';

export default defineConfig({
  entry: ['src/**/*.ts', '!src/**/*.test.ts'],
  format: ['esm', 'cjs'],
  unbundle: true,
  dts: true,
  sourcemap: true,
  exports: true,
  outDir: 'dist',
});
```

`exports: true` is the only writer of the `exports` map. Do not hand-maintain per-function export entries.

`package.json` `files`: `["dist"]`. Publish the package root (not a rewritten `dist/package.json`). `main` / `module` / `types` point at `dist` outputs tsdown generates.

Delete: `rollup.config.cjs.js`, `rollup.config.esm.js`, `tsconfig.prod.cjs.json`, `tsconfig.prod.esm.json`, `tsconfig.prod.types.json`, `scripts/release.js`.

### Types / tsconfig

- `target`: ES2020
- `strict`: true
- `moduleResolution`: `bundler`
- Drop unused `experimentalDecorators` / `emitDecoratorMetadata` / `reflect-metadata`.

## Testing

- Runner: **Vitest** (replace Jest + ts-jest).
- Location stays `test/{category}/{function}.spec.ts`.
- Coverage provider: v8. Thresholds: 90% branches, functions, lines, statements (same as today).
- Use `vi.useFakeTimers()` for `debounce`, `throttle`, `delay`, `timeout`, `retry` backoff.
- Add `expectTypeOf` tests for `get`, `pick`, `omit`, `groupBy`, `retry`, `debounce` return types.
- Update `remove` tests for the immutable contract: input array unchanged; return value is the removed items.
- AbortSignal tests for `delay`, `timeout`, `retry`.
- Dependabot PRs that only bump Docusaurus/React-18/Jest/Rollup are closed as superseded. Bumps that still apply (TypeScript 5.9 already on main, eslint-plugin updates if we keep ESLint for `src`) are folded into the 1.0 toolchain upgrade.

Quality gates: `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build`. Zero ESLint warnings.

## Documentation site

Replace `website/` Docusaurus app with a **Vite + React 19 + TypeScript + React Router** app. Keep the workspace name `website`.

### Routes (`basename` = `/kit/`)

| Path                   | Page                                                                                          |
| ---------------------- | --------------------------------------------------------------------------------------------- |
| `/`                    | Catalog home: one-line pitch, install snippet, search box, category cards, featured functions |
| `/guide`               | Install, import styles, tree-shaking, 1.0 breaking notes                                      |
| `/guide/agents`        | How agents should use `llms.txt` and the repo skills                                          |
| `/api`                 | Full function index (same data as home search, denser)                                        |
| `/api/:category`       | Category listing                                                                              |
| `/api/:category/:name` | Function page: signature, JSDoc, examples, **live playground**                                |
| `/skills`              | Renders the three skill overviews                                                             |
| `/zh` and `/zh/*`      | Chinese locale of the same tree                                                               |

Locale is a path prefix (`/` English, `/zh` Chinese). A header toggle swaps the prefix and keeps the rest of the path.

### Catalog generation

`scripts/generate-catalog.ts` walks `src/*/*.ts` (skip `index.ts` and `types/`), parses exported function name, category (parent dir), JSDoc summary, params, examples, and signature text with the TypeScript compiler API (`typescript` is already a dependency; do not add `ts-morph`). Writes:

- `website/src/generated/catalog.ts` (committed; CI runs `pnpm docs:catalog --check` and fails if it would change)
- `llms.txt` at repo root (also committed; same `--check`)

The website does **not** parse source at runtime. `pnpm docs:build` assumes the catalog is already current.

### Playground

On each function page, a small editor prefilled with that function’s first `@example`. Evaluate in-browser against the workspace build of `@rabjs/kit`. Use a lightweight in-browser eval (`new Function` + captured `console` / return value), not a full Sandpack, unless an example needs JSX.

### Visual direction

Not a Docusaurus clone and not a generic purple gradient landing page. Catalog home is a dense, typographic index: strong wordmark, search first, category cards second. Implementation follows the frontend-design skill at build time. GitHub Pages base path remains `/kit/`.

### i18n

- UI chrome: `website/src/i18n/en.ts` and `zh.ts`.
- Guide prose: `website/src/content/en/*.md` and `zh/*.md`.
- API summaries: English from JSDoc; Chinese from `website/src/i18n/api.zh.ts` keyed by `category/name`, falling back to English if missing. Do not require 100% Chinese JSDoc in `src/`.

### Delete

Entire Docusaurus tree: `website/docs`, `website/blog`, `website/i18n`, `website/docusaurus.config.ts`, `website/sidebars.ts`, classic preset deps. Keep only assets we still need (favicon).

## Agent assets

### `llms.txt`

Plain text at repo root, regenerated by the catalog script:

```
# @rabjs/kit
Typed lodash-shaped utilities. Named exports only. Immutable remove.

## Import
import { chunk, retry } from '@rabjs/kit'
import { chunk } from '@rabjs/kit/array/chunk'

## Functions
### array
- chunk(array, size): Split array into groups
- remove(array, predicate): Return removed items; does not mutate
...
```

### `AGENTS.md`

Tells coding agents working **in this repo**: named exports only, one function per file, JSDoc + test + catalog regen, run `pnpm test` / `pnpm build`, never hand-edit `exports`.

### Skills (repo only)

Three skills under `skills/<name>/SKILL.md`. They are documentation for agents that clone or are pointed at this repo. They are **not** published to npm and **not** copied to the user’s personal skills directory.

1. **`using-rabjs-kit`**
   - Trigger: writing application code that needs array/object/promise helpers, or choosing between native APIs and `@rabjs/kit`.
   - Content: import styles, when to use native (`Array.flat`, `Object.keys`) vs kit (`groupBy`, `retry`, `cloneDeep`), immutable `remove`, no default import.
2. **`adding-kit-function`**
   - Trigger: adding or changing a function in this repository.
   - Content: file layout, JSDoc contract, Vitest template, category index, do not edit `exports`, run catalog generator.
3. **`migrating-lodash-to-kit`**
   - Trigger: replacing `lodash` / `lodash-es` with `@rabjs/kit`.
   - Content: name map for functions we implement, `remove` mutation difference, no `_.chain` / `fp`, deep import equivalents.

Skill descriptions start with “Use when…” and do not summarize workflow. Author against skill-design-principles when writing them.

## CI / CD

### CI (every push / PR)

Single workflow `.github/workflows/ci.yml`:

1. pnpm + Node 22
2. `pnpm install --frozen-lockfile`
3. `pnpm lint` (ESLint, max warnings 0)
4. `pnpm prettier:check`
5. `pnpm typecheck`
6. `pnpm test` (coverage)
7. Codecov upload (same secret as today, `fail_ci_if_error: false`)
8. `pnpm build`
9. `pnpm docs:catalog --check`
10. `pnpm docs:build`

### Release (Changesets)

`.github/workflows/release.yml` on `push` to `main`, plus `workflow_dispatch`:

- `changesets/action@v1`
- If unpublished changesets exist: open/update the Version PR (title `chore: version packages`).
- If the Version PR is merged (versions already bumped, no remaining changesets): `pnpm build` then `pnpm publish --no-git-checks` with `NPM_PUBLISH_TOKEN`, and create a GitHub Release from the changelog.
- Concurrency group `release` so two publishes cannot interleave.

Developers add a changeset in the same PR as the code change (`pnpm changeset`). The 1.0 landing PR includes a `major` changeset.

Delete: `scripts/release.js`, `tag-release-workflow.yml` (tag-driven GitHub Release), `npm-publish-on-release.yml` (release-event publish). Tagging is no longer the publish trigger.

Keep a thin `deploy-docs.yml` on `main`. Destination: GitHub Pages, artifact = `website/dist` (Vite `build.outDir`, not the library `dist/`), base `/kit/`. Upgrade leftover `pnpm/action-setup@v2` to `v4`. Do not fold docs deploy into the Changesets publish job: docs should update on every main push, including README-only commits that have no npm version bump.

### Dependabot

- Directory `/`, weekly not daily.
- Timezone `Asia/Shanghai`.
- Ignore `website` Docusaurus packages (they will be gone).
- Close open PRs that bump `rollup`, `react`/`react-dom` for Docusaurus, `ts-morph` if unused, and `@types/node@25` if we pin Node 22 types.

### Other workflows

- Keep or drop `lock-closed-issues` (no product impact). Prefer drop if unused.
- Drop `auto-merge-dependabot` until 1.0 is stable, or keep with the new ignore list.

## Key Decisions

1. **Full API + AI layer, not a slim kit.** Owner chose both “modern lodash replacement” and “full surface + AI extras.” Deleting native wrappers would fight that choice.
2. **1.0 breaking cleanup.** Default exports gone, `any` tightened, `remove` immutable, generated `exports`. Version is `0.0.3`; this is the major.
3. **tsdown unbundle + `exports: true`.** Replaces Rollup and the handwritten export map. Dual ESM/CJS with per-file output.
4. **Vitest over Jest.** Same test files, modern runner, native TS, `expectTypeOf`.
5. **Catalog-first Vite docs.** Search and category cards on the home page; playground lives on the function page. Docusaurus deleted.
6. **Changesets, not git tags, publish to npm.** Matches “workflow 自动化发包” without the TypeDI tag script.
7. **Skills are repo assets only.** Three skills + `llms.txt` + `AGENTS.md`. Not installed into personal skill directories.
8. **AbortSignal on `delay` / `timeout` / `retry`.** Additive options; omitted behavior unchanged.
9. **Two README files, not one bilingual blob.** English default for npm; Chinese sibling linked at the top.
10. **GitHub Pages base stays `/kit/`.** Avoids breaking the existing site URL.
