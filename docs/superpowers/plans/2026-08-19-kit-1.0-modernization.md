# @rabjs/kit 1.0 Modernization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `@rabjs/kit@1.0.0` — full lodash-shaped TypeScript utilities, tsdown dual publish, Vitest, catalog-first Vite docs, Changesets npm publish, and repo-local agent skills.

**Architecture:** Root package stays the publishable library. `website/` is a private Vite + React 19 app. `src/` is the source of truth; `scripts/generate-catalog.ts` writes committed `website/src/generated/catalog.ts` and `llms.txt`. tsdown unbundle mode emits ESM+CJS+dts and the `exports` map. Skills live only under `skills/`.

**Tech Stack:** TypeScript 5.9, tsdown, Vitest, ESLint 9, Vite 7, React 19, React Router 7, Changesets, pnpm 10, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-08-19-kit-1.0-modernization-design.md`

## Global Constraints

- Keep every current public function. Do not delete categories or native wrappers (`isArray`, `keys`, `padStart`).
- Function names and primary argument order stay lodash-compatible.
- Named exports only. Delete every `export default`.
- `remove(array, predicate)` returns the removed items and does **not** mutate `array`.
- No `any` in public signatures. Use generics or `unknown`.
- `delay` / `timeout` / `retry` accept optional `AbortSignal` (additive).
- Node `>= 20`. Package `"type": "module"`. `sideEffects: false`.
- Coverage floor: 90% branches, functions, lines, statements.
- Docs base path `/kit/`. Locale prefix `/` (en) and `/zh`.
- Skills stay in-repo. Do not copy to `~/.grok/skills` or `~/.agents/skills`.
- Do not hand-edit `package.json` `exports`. tsdown `exports: true` owns that field.
- Work on branch `chore/v1-modernization`. Do not implement on `main`.
- Follow TDD for behavior changes: failing test first, then implementation.

- [ ] **Step 3: Implement immutable `remove`**

```ts
export function remove<T>(
  array: readonly T[],
  predicate: (item: T, index: number) => boolean,
): T[] {
  if (!Array.isArray(array)) {
    return [];
  }
  return array.filter((item, index) => predicate(item, index));
}
```

Note: lodash’s `remove` returns the **removed** items. `filter(predicate)` is exactly that set, without mutating. Leftovers are `array.filter((item, i) => !predicate(item, i))` or `partition`.

### Task 4: AbortSignal on `delay`, `timeout`, `retry`

**Files:**
- Modify: `src/promise/delay.ts`, `src/promise/timeout.ts`, `src/promise/retry.ts`, `src/types/index.ts`

**Interfaces:**
- `delay<T = void>(ms: number, value?: T, signal?: AbortSignal): Promise<T | void>`
- `timeout<T>(promise: Promise<T>, ms: number, message?: string, signal?: AbortSignal): Promise<T>`
- `retry<T>(fn: () => T | Promise<T>, options?: RetryOptions): Promise<T>`
- `RetryOptions` = `{ maxAttempts?: number; delay?: number; backoff?: number; onRetry?: (attempt: number, error: Error) => void; signal?: AbortSignal }`

If `signal` is already aborted, reject immediately with `signal.reason` (or `DOMException`/`Error` named `AbortError`). If aborted while waiting, clear the timer and reject the same way. Existing callers that omit `signal` are unchanged.

- [ ] **Step 1: Add failing AbortSignal tests**

});

it('rejects and does not wait when aborted during the delay', async () => {
  vi.useFakeTimers();
  const controller = new AbortController();
  const pending = delay(5000, 'x', controller.signal);

});
```

Add the same pattern to `timeout` (4th arg) and `retry` (`options.signal`, including abort between attempts).

```

- [ ] **Step 3: Implement AbortSignal**

Shared helper in `src/promise/abort.ts` (not a public export from `src/index.ts`):

```ts
export function abortError(signal: AbortSignal): unknown {
  return signal.reason ?? new DOMException('This operation was aborted', 'AbortError');
}

export function onAbort(signal: AbortSignal, cb: () => void): () => void {
  if (signal.aborted) {
    cb();
    return () => undefined;
  }
  const handler = () => cb();
  signal.addEventListener('abort', handler, { once: true });
  return () => signal.removeEventListener('abort', handler);
}
```

`delay`: if aborted, reject; otherwise `setTimeout` + abort listener that `clearTimeout`s.

`timeout`: race original promise, timer reject, and abort reject; always `clearTimeout` on settle.

`retry`: check signal before each attempt and while sleeping; do not schedule the next attempt after abort.

Fix `src/types/index.ts` `RetryOptions.backoff` to `number` (implementation already uses a multiplier). Delete the unused `'linear' | 'exponential'` union.
